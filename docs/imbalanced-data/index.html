Logistic correction

The sampling identity and rare-events correction

From probabilities to counts

Logistic regression assumes that log[p(x)/(1 − p(x))] = α + βx. For this illustration, assume that relationship is true. Within a group at a given x, let N+ and N− count positives and negatives, and let N = N+ + N−. Substituting their shares cancels the common total:

log[(N+/N)/(N−/N)] = log(N+/N−)

Two predictor values illustrate the assumed line: at x = 0 and 1, the positive shares are 1% and 50%, giving logit p(x) = log(99)(x − 1). Each plotted point is a group. The equal-size groups compare conditional class ratios; they do not show predictor frequencies. In the full population, 99% of observations have x = 0 and 1% have x = 1, making the overall event rate 1.49%. Two points illustrate linearity rather than test it.

Thin the negatives and expand the logarithm

Keep every positive and randomly retain a share s of negatives, with the same retention probability at every x. Here 0 < s ≤ 1, and retaining 10% means s = 0.10. The animation shows expected retained counts; an actual random sample fluctuates.

The new group total is N′ = N+ + sN−. It also cancels when we form the sampled odds:

log[(N+/N′)/(sN−/N′)]
= log[N+/(sN−)]
= log(N+/N−) − log s

Writing q(x) for the sampled positive probability gives logit q(x) = (α − log s) + βx. The added term changes the intercept. Retaining 10% adds log(10) ≈ 2.30 at both predictor values, preserving the slope. Correction adds log(0.10) to shift the line back.

Random sampling with the same inclusion probability for everyone would shrink both class counts together and leave the true conditional odds unchanged.

A connection to rare-events logistic regression

Political scientists Gary King and Langche Zeng discuss this sampling adjustment as prior correction in “Logistic Regression in Rare Events Data” (2001), §4.1. Their rare-events work also addresses finite-sample estimation bias, which is a separate problem from the sampling shift shown here.

If positives and negatives have retention rates s1 and s0, the population correction is log(s0/s1). Equivalently it is logit(π) − logit(ρ), where π is population prevalence and ρ is sampled prevalence.

The conditional odds identity requires class-only selection with constant inclusion probabilities within each class. It holds even when true log odds are curved. Preserving the slopes of a fitted logistic model additionally requires correct specification, an intercept, and no penalty; the statement describes population fits and large-sample behavior.

Try a different negative retention share

A constant log-odds correction preserves score ordering and AUC. A chosen probability threshold can still flag different cases.

An exact synthetic population

These results minimize expected logistic cross-entropy over all straight-line logits. They use exact population masses, with no random sample or unfinished optimization. Both fits include a free intercept and use no penalty.

Randomly retaining negatives leaves the true log-odds curve a vertical translation. But it changes which parts of that curve matter most to the best straight-line approximation. The fitted slope can change, so a constant correction cannot restore the original fit. Inverse-selection weighting of the sampled loss recovers the original population objective.

King & Zeng (2001), §4.1: prior correction in rare-events logistic regression.

Fithian & Hastie (2014), §2.2, discusses why ordinary case-control logistic fits can behave differently under misspecification. This numerical example illustrates that mechanism; it does not claim downsampling improves prediction.

Finite data, fitted models, random retention

For each example, generate 200,000 training observations and a separate, untouched test sample of 200,000 observations. Fit an unpenalized logistic regression with a free intercept and one linear predictor. Keep every positive and retain each negative independently with probability 0.10, then fit the same model again. The displayed sample is the first draw; it was not selected for a particular result.

The correctly specified example has 99% of population observations at x = 0 and 1% at x = 1. The true positive shares at those values are 1% and 50%, with log odds log(99)(x − 1). The curved example has predictor shares 0.68, 0.20, 0.08, 0.03, and 0.01 at x = 0, 1, 2, 3, and 4; its true log odds are −6 + 0.3x + 0.5x². Outcomes are random Bernoulli draws at the corresponding event probabilities.

Prior correction adds log(0.10) to the sampled intercept and leaves its slope unchanged. It uses the known retention probability. A finite random draw need not retain exactly 10% of negatives or reproduce the original fitted slope.

Match the training objective to the prediction target

For probability prediction evaluated by log loss at the natural prevalence, the original imbalanced data fit wins in this curved example: test loss is 0.053220, versus 0.053926 after correcting the downsampled fit. Keeping all positives and 10% of negatives raises the training positive share from 2.53% to 20.54%; this sample is rebalanced but not 50/50.

At the population level, fitting the natural distribution minimizes its expected log loss within this linear logit model class, even when the model is misspecified. Rebalancing can change that approximation; an intercept correction need not recover it. Finite fits and test samples can still fluctuate. See Fithian & Hastie (2014), §§1.3–2.

If downsampling saves computation but the original probability prediction objective is still the target, inverse-selection weighting preserves that population objective. With 10% negative retention, give retained negatives weight 10 and positives weight 1. The retained weighted fit still has sampling variation. Recall, decision costs, and tree split selection can call for different objectives; this comparison does not settle those choices.

Changing the class mixture changes the preferred split

This is a new numerical example using entropy as the tree impurity criterion. At the root, two binary features supply the two candidate splits. A sends 50% of positives and 0% of negatives left. B sends 90% of positives and 10% of negatives left. A joint distribution exists: generate the two features independently conditional on the label. Treat the stated proportions as population quantities; random finite samples fluctuate around them.

The right leaf contains everyone not sent left: A receives the remaining 50% of positives and all negatives; B receives the remaining 10% of positives and 90% of negatives. Each leaf card shows its counts and its positive share. The bars show composition within a leaf. Changing the training balance updates both leaves while preserving these routing rules.

The scroll animation keeps all 100 positives and randomly thins negatives, reducing their expected count from 9,900 to 100. At the end, 1/99 of negatives remain: about 1.01% retained and 98.99% removed. The training sample is then 50% positive. Intermediate retention shares can produce fractional expected counts.

A’s left leaf contains 50 positives and no negatives, so it stays 100% positive. Its right leaf keeps 50 positives while its negative count falls from 9,900 to 100. Its positive share therefore rises from 50/(50 + 9,900) = 0.503% to 50/(50 + 100) = 33.333%. B’s two leaves also lose negatives while keeping their positive counts. The class composition changes even though the split rules do not.

Write p for the positive proportion at the parent, q for the proportion sent left, and pL, pR for the positive proportions in the two children. The entropy decrease, or information gain, is

H(p) = −p ln p − (1 − p) ln(1 − p)
Δ = H(p) − q H(pL) − (1 − q) H(pR)

Natural logs measure entropy and information gain in nats. Use H(0) = H(1) = 0. A different log base rescales gains and cutoffs without changing the rankings.

The entropy plot places the two child proportions on H(p) and joins them with a chord. Because p = q pL + (1 − q) pR, the chord height at the parent’s positive share is the weighted child entropy. Its vertical gap to the curve is information gain. The lower chord at that parent gives the larger gain. Left and right labels refer to the tree children; either child can lie farther right on the plot.

If a split sends fraction a of positives and fraction b of negatives left, then q = pa + (1 − p)b, pL = pa/q, and pR = p(1 − a)/(1 − q). Class-uniform downsampling preserves a and b in the retained population, while changing p, q, and the child proportions. The two gains need not change by the same factor.

For example, take 100 positives and 9,900 negatives. A has left counts (50, 0) and right counts (50, 9,900); B has (90, 990) and (10, 8,910). Retain all positives and 1/99 of negatives. The expected negative counts become 100 in A’s right child, and 10 and 90 in B’s children. The table follows directly from the weighted child entropies. No extra positive information has been created.

Ranking and stopping are different decisions

At 1% positives, ΔA > ΔB. With both candidates otherwise admissible, any minimum-gain cutoff that lets B pass also lets A pass. The greedy tree still chooses A. A cutoff above A’s gain makes the tree stop. There is no cutoff that selects B here.

Scikit-learn’s min_impurity_decrease compares the gain multiplied by the node’s share of the full training sample. At this root that factor is one. At any fixed node it is common to its candidate splits, so it cannot reverse their ranking.

Other hyperparameters can change the candidate set. Here A’s tiny left leaf occupies 0.5% of the original sample: setting min_samples_leaf to 1% excludes A while allowing B. More depth may recover distinctions later. These possibilities do not imply that a global hyperparameter grid reproduces rebalancing throughout a tree. The grid searches outputs of a greedy procedure; it does not enumerate all possible tree structures.

What this establishes for a forest

For a stump, these two partitions yield ROC AUCs of 0.75 and 0.90, respectively. Changing A’s prediction threshold cannot recover a distinction among observations that A puts in the same leaf. A’s pure positive leaf can still be useful: a higher AUC does not make B preferable for every operating cost.

The same split-ranking mechanism operates inside random-forest trees whenever both candidates are considered. It is a possibility result about a learning algorithm, not a theorem that balancing improves a fully tuned forest. Feature subsampling, deeper trees, and finite-sample variability affect the final ensemble. Class weighting can target the same rebalanced population criterion without discarding observations, although the fitted forests need not be identical.

02 / The efficiency argument

Spend less time on the common class.

Now consider one million training observations with 1% positives: 10,000 events and 990,000 non-events.

Keep all 10,000 events and randomly retain 10,000 non-events. One pass now processes 20,000 examples instead of a million—a 50-fold reduction in example visits.

That can free time for tuning, richer models, or more refits. It is a computational argument, with a statistical price: we discarded information from the majority class.

This compares examples per pass, not measured wall-clock speed. Scanning and sampling the original data still have a cost.

02 / A fixed update budget

Give each batch more rare examples.

At 1% prevalence, a random batch of 128 contains just 1.28 positive examples on average. About 28% of such batches contain none.

Sampling from a 50/50 distribution gives 64 positives on average. It changes how often training encounters the rare class and can change the variability of its updates.

Repeated visits are not new information. Upweighting the loss on the full data also changes influence, but does not by itself reduce how many examples must be processed.

02 → 03 / The fork in the argument

Which destination are we optimizing for?

Natural loss: 0.01 L1 + 0.99 L0
Balanced loss: 0.50 L1 + 0.50 L0

Unweighted balancing changes the objective. Each class now has equal influence, regardless of its prevalence.

To keep the natural objective under 50/50 sampling, weight positive losses by 0.02 and negative losses by 1.98. In expectation, that recovers the original loss.

Efficient sampling and changing priorities can be separated. Sampling affects which examples get visited; loss weights determine their contribution. Whether the resulting updates are more efficient depends on the problem.

More examples / The learning argument

Unlimited compute. Limited capacity.

Imagine a model that may use only one binary signal. It can split on A or B, then assign the best probability to each branch.

Reuse the same splits: A fires for 50% of positives and no negatives; B fires for 90% of positives and 10% of negatives.

We can optimize both models exactly. There are no unfinished training runs here—only a choice about which signal earns the model’s single slot.

Synthetic population, 1% positive prevalence. The signals can be generated independently conditional on the label. Their conditional rates stay fixed as we change the loss weights.

More examples / Optimize the natural loss

The narrow signal wins.

Under the natural 1/99 class mixture, model A has lower optimized log loss. Its very low false-positive rate makes it valuable for estimating probabilities in this rare-event population.

Training longer will not make this objective prefer B. A is already the global optimum within our two-model family.

Each candidate’s two leaf probabilities are also optimized. The figure uses exact expected cross-entropy, measured in nats; lower is better.

More examples / Optimize the balanced loss

Now the broader signal wins.

Give positives and negatives equal influence. Model B now has lower optimized log loss, so the model spends its one slot on B.

This is a change in learned structure. B catches more positives, while admitting more negatives. Its AUC is 0.90, compared with about 0.75 for A.

Move the influence slider. The preferred signal changes well before the classes reach 50/50. Equal balance is a candidate to try, not a privileged optimum.

More examples / Beyond an intercept

A correction cannot restore a discarded signal.

Correct B’s probabilities back to 1% prevalence. Its AUC stays 0.90. The correction restores the prior within its leaves; it does not make the model use A.

Nor can changing a threshold on model A reproduce model B. They rank some observations in the opposite order. The ROC curves cross: neither signal wins at every false-positive rate.

This demonstrates a possible benefit at convergence for a model with restricted capacity. It does not prove that balancing always improves flexible models or their learned representations.

More examples / Better according to what?

The gain has a price.

Flag the higher-score branch of each model. A has 100% precision and 50% recall. B has about 8% precision and 90% recall.

The balanced objective improves AUC and the best balanced accuracy in this example, while the corrected B model has worse natural-population log loss. More false alarms may be worth it—or may make B unusable.

Evaluate on untouched data at the deployment prevalence. Tune sampling, weighting, and thresholds inside training folds. Choose a metric or explicit cost that reflects the decision.

The operating points shown flag signal = 1. They are not both obtained by thresholding the corrected probabilities at 0.5. A balanced training distribution is not a balanced test population.

Optional implementation example

The basics of imblearn

This optional example uses the imbalanced-learn package, imported as imblearn. Use whichever tools suit your work. Its samplers change the training rows and labels together with fit_resample(X, y). Resampling is a model choice to evaluate, rather than a requirement imposed by rare labels.

python -m pip install scikit-learn imbalanced-learn
ToolWhat it does
RandomUnderSamplerRandomly retains fewer majority observations. The direct analogue of the thinning in this lesson.
RandomOverSamplerIts basic form repeats minority observations. Repetition adds influence, not independent information.
SMOTEInterpolates minority examples using neighbors. This changes feature geometry as well as class counts; the preceding class-only sampling correction does not directly apply.
BalancedRandomForestClassifierConstructs a class-balanced draw for each tree, allowing different trees to use different majority observations.

For binary undersampling, sampling_strategy is the desired minority / majority count ratio after resampling. 1.0 means 50% minority, 0.25 means 20%, and 0.1 means about 9.1%. It is not the fraction of majority cases retained. A requested ratio below the original ratio cannot be achieved by removing majority cases.

Keep resampling inside cross-validation

The example holds out the test set at its natural class mix, then passes an imblearn.pipeline.Pipeline to GridSearchCV. Each fit resamples its training fold; the validation fold and later test predictions keep all their rows. The ordinary scikit-learn pipeline does not implement sampler steps.

On a separate synthetic dataset, the runnable example compares no resampling with several undersampling ratios and tunes tree depth and leaf size together. It also tunes a balanced forest separately. Average precision (AP) summarizes precision across recall levels. CV compares each sampling choice with the tuned baseline; only the winner is evaluated on the test set.

"""Compare resampling choices using untouched validation folds and test data.

Install: python -m pip install scikit-learn imbalanced-learn
Run: python imblearn_demo.py
"""
from collections import Counter

from imblearn.ensemble import BalancedRandomForestClassifier
from imblearn.pipeline import Pipeline
from imblearn.under_sampling import RandomUnderSampler
from sklearn.datasets import make_classification
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import average_precision_score, roc_auc_score
from sklearn.model_selection import GridSearchCV, StratifiedKFold, train_test_split


X, y = make_classification(
    n_samples=4000, n_features=10, n_informative=5,
    n_redundant=2, weights=[0.97, 0.03], flip_y=0,
    random_state=42,
)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=42,
)
cv = StratifiedKFold(n_splits=3, shuffle=True, random_state=42)
# Each validation fold and the test set have only 30 positives; AP can be noisy.

# A sampler changes BOTH X and y. Use imblearn's Pipeline.
# GridSearchCV calls fit on each training fold; validation is not resampled.
pipeline = Pipeline([
    ("sample", "passthrough"),
    ("forest", RandomForestClassifier(
        n_estimators=100, criterion="entropy", random_state=42, n_jobs=1,
    )),
])
common = {
    "forest__max_depth": [4, None],
    "forest__min_samples_leaf": [1, 5],
}
grid = [
    {**common, "sample": ["passthrough"]},
    {**common,
     "sample": [RandomUnderSampler(random_state=42)],
     "sample__sampling_strategy": [0.1, 0.25, 1.0]},
]
search = GridSearchCV(
    pipeline, grid, cv=cv, scoring="average_precision",
    n_jobs=-1, refit=True, error_score="raise",
)
search.fit(X_train, y_train)

# A separate comparison: the forest creates a fresh balanced draw per tree.
# Explicit sampling settings avoid ambiguity across imblearn versions.
balanced_search = GridSearchCV(
    BalancedRandomForestClassifier(
        n_estimators=100, criterion="entropy", sampling_strategy="all",
        replacement=True, bootstrap=False,
        random_state=42, n_jobs=1,
    ),
    {"max_depth": [4, None], "min_samples_leaf": [1, 5]},
    cv=cv, scoring="average_precision", n_jobs=-1,
    refit=True, error_score="raise",
)
balanced_search.fit(X_train, y_train)

print("Training counts:", Counter(y_train))
print("Untouched test counts:", Counter(y_test))
print("Best CV AP by sampling choice (mean ± fold SD):")
results = search.cv_results_
for ratio in [None, 0.1, 0.25, 1.0]:
    candidates = [i for i, params in enumerate(results["params"])
                  if params.get("sample__sampling_strategy") == ratio]
    best = max(candidates, key=lambda i: results["mean_test_score"][i])
    label = "No resampling" if ratio is None else f"Minority/majority={ratio:g}"
    print(f"  {label}: {results['mean_test_score'][best]:.4f} ± "
          f"{results['std_test_score'][best]:.4f}")
spread = balanced_search.cv_results_["std_test_score"][balanced_search.best_index_]
print(f"  Balanced forest: {balanced_search.best_score_:.4f} ± {spread:.4f}")
for label, result in [
    ("Resampling pipeline", search),
    ("Balanced forest", balanced_search),
]:
    print(label, "parameters:", result.best_params_)

# Choose the method on CV results, then evaluate that choice once on test data.
selected = max([search, balanced_search], key=lambda result: result.best_score_)
score = selected.predict_proba(X_test)[:, 1]
print("Selected model test AP:", round(average_precision_score(y_test, score), 4))
print("Selected model test ROC AUC:", round(roc_auc_score(y_test, score), 4))
# AP and ROC AUC assess scores, not a chosen classification threshold.
# Tune thresholds or calibrate probabilities using separate training-only folds.

One undersample per fit, or a new draw per tree?

A RandomUnderSampler → RandomForestClassifier pipeline makes one retained training pool for that fit. Its forest then draws trees from that pool. A balanced forest instead builds a new balanced sample for every tree. In the example, sampling_strategy="all", replacement=True, and bootstrap=False make the internal sampling explicit: draw with replacement from each class, without a second bootstrap stage.

A balanced training sample changes score levels as well as possible partitions. If calibrated probabilities matter, check them on data at deployment prevalence and calibrate using training-only validation data. A prior correction of arbitrary fitted forest scores is not a calibration guarantee. Choose a classification threshold separately when the actual task requires decisions.

The practical judgment

Balance for a reason.

  1. For probabilities: account for how sampling changed the prior. A threshold problem alone need not require retraining.
  2. For efficiency: test whether a smaller training set gives useful results sooner. Keep informative negatives.
  3. For learning: balancing can change which split a greedy tree prefers, even when both candidates clear the impurity cutoff. Compare sampling choices on untouched validation data.

I would treat balancing as a tuning choice, not a ritual. A rare label by itself is not evidence that a model cannot learn.

Where this extends and corrects the notes

The notes’ intercept correction has the correct sign. The opening develops linear log odds, cancels the group totals, and shows why thinning negatives adds a constant before illustrating the intercept shift. A short curved-truth comparison distinguishes the exact odds correction from what a misspecified fitted model does. “Unbiased” is too strong for finite-sample logistic estimates. The exact odds correction and the correctly specified logistic slope result need separate assumptions. The one-signal example develops the learning argument without relying on incomplete optimization.
