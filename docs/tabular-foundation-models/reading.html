Tabular foundation models

Following Christoph Molnar’s book. This lesson follows the bear-survival task through a real miniature PFN training run, its actual inference calculations, an exact Bayesian illustration, and a measured XGBoost diagnostic. The proposed explanation for TabPFN’s behavior is identified as a hypothesis.

The data-generating process

This is the true data-generating process.

Bear type and strategy determine the probability of survival. Each simulated outcome is a random draw using the probability at its leaf.

This tree specifies the true conditional outcome distribution in our simulation. A brown bear with a fight response has survival probability logistic(−1) ≈ 26.9%; a brown bear with a lie-down response has logistic(1) ≈ 73.1%. For black bears, those probabilities reverse: fight gives 73.1%, and lie down gives 26.9%. Bear type and strategy are independent balanced binary variables, so the four leaves are equally likely. Conditional on those features, survival is a Bernoulli draw with the displayed probability. This is a stipulated simulation rule, not a fitted tree. The learner will receive sampled encounters without being given this tree. Later we add independent continuous distractors, which do not change these probabilities.

Depth 2: split on bear type, then strategy. Bear type and strategy are independent, each with equally likely values.

Learning to use a table

One rule within a table. Different rules across tables.

Our opening simulation uses rule A. For pretraining, choose A or its reverse, B, once per table. Every encounter in that table shares the chosen rule.

We built and trained a small educational prior-data fitted network for this two-world family. It is not TabPFN. World A is the opening bear rule; B reverses all four survival probabilities. Each task chooses its world with equal probability, then draws four labeled context encounters and one query encounter. Bear type and strategy are independent balanced binary features; outcomes are conditionally independent Bernoulli draws. Crucially, the world is shared within a table. If we instead drew a fresh world for every row, context outcomes would tell us nothing about the query. Real tabular foundation models train on much broader families of tasks.

The network is not told which rule was chosen. This deliberately small task family makes the learning problem visible.

Learning to use a table

The hidden answer supplies the training signal.

If the query outcome is survival, a prediction of 74.0% incurs log loss 0.301. Backpropagate the loss to update the shared network weights.

This calculation uses our trained model’s actual prediction for the displayed context. Take a possible held-out draw Y*=1. Binary cross-entropy is −[Y* log(q) + (1 − Y*) log(1 − q)], so the loss here is 0.300725. If z is the output logit, its derivative is q − Y*, here -0.260. Backpropagation passes that signal through the decoder, attention projections, and encoders. Training averages the losses of 256 separate tasks before each Adam update. An individual contradictory outcome can push the other way; optimizing across noisy tasks rewards useful probabilities, not certainty. The diagram illustrates the update operation without inventing a numerical post-update prediction.

Learning to use a table

Using the context lowers prediction loss.

Without context, equally common opposite rules average to 50% survival for every query. The labeled encounters contain information that this pooled prediction discards.

The context-blind benchmark predicts 0.5, the best possible prediction when the two worlds are equally likely and the context is ignored. Its test log loss is 0.693. The trained miniature network achieves 0.630; exact posterior predictive inference under the known generator achieves 0.628. Learning to use a table

Train one network across all those exercises.

We made 4,000 updates using 256 new tasks per update. The encoders, attention projections, and decoder learned together from hidden-outcome errors.

The model starts with randomly initialized neural-network weights. Its inputs contain raw binary bear, strategy, and context-label columns. Neither world identity, the matching-pair indicator, the exact posterior, nor a Bayesian prediction is supplied as an input or training target. A context-row MLP and query MLP feed a single cross-attention head; an MLP decoder produces a survival logit. Adam updates all parameters through the sampled query loss. The final checkpoint is fixed by the training schedule, without selecting it against test results. The plotted curve reports observed log loss on the same 2,048 independent validation tasks at each checkpoint, not the training minibatch loss. An actual prediction

Freeze the weights. Supply a new context.

The same trained network returns 74.0% for context A and 23.6% for context B. Its intermediate calculations change because the input changes.

This is in-context learning. The function computed by the trained network is fixed, but it is a function of both the query and the labeled context. Replacing the context changes the row vectors, attention computations, pooled representation, and final prediction. In ordinary task-specific neural-network training, fitting a new dataset changes weights; here, pretraining has already learned a way to use the dataset as input. These particular predictions are imperfect: their exact Bayesian targets are approximately 72.3% and 27.7%. Learning the inference procedure does not guarantee exact inference or calibration.

An actual prediction

First, turn each labeled row into a vector.

In our teaching model, an MLP maps bear type, strategy, and survival into 32 numbers. A separate MLP encodes the query’s two known features.

The displayed row is Black + Fight + Survived, encoded as (0,0,1). The same context encoder is applied to every labeled row. Its nonlinear transformations allow the resulting vector to depend jointly on features and outcome; the coordinates have no assigned human-readable meanings. This small model encodes whole rows. Molnar’s nanoTabPFN explanation instead embeds cells and alternates attention across rows and columns. The details differ, while both designs provide learned representations through which the context can affect a query.

An actual prediction

Attention combines the context vectors.

The query produces a query vector; each labeled row produces a key and a value vector. Softmax scores determine the weighted sum of those values.

Linear projections of the encoded query and context produce Q, K, and V. With width 32, the scores are Q·K_i/√32; softmax converts them into nonnegative weights a_i summing to one. The pooled representation is c = Σ a_i V_i. The diagram shows the first two coordinates of each actual 32-dimensional value vector and verifies their weighted sum. The decoder also retains the query representation. The weights in this example are fairly even: useful information is spread across the context, so a sharply focused lookup is not required. These attention weights describe a computation in this particular model; they are not posterior probabilities over worlds or an explanation of feature importance.

An actual prediction

Decode that representation into a probability.

The decoder combines the query vector with the attention output. Its logit 1.047 becomes a survival probability of 74.0% through the sigmoid function.

Concatenating the 32-dimensional query representation and the 32-dimensional attention output gives the decoder 64 inputs. A hidden ReLU layer followed by a scalar output produces the logit; sigmoid maps it into (0,1). During pretraining, query-label error could flow backward through this full computation. During inference, there is only the forward calculation. The network was trained to predict outcomes; it was not trained to reproduce explicit posterior weights. Under the task generator, the log-loss-optimal answer is nevertheless the posterior predictive probability.

σ(1.047)≈0.740\sigma(1.047)\approx 0.740σ(1.047)≈0.740

The entire input-to-probability calculation uses fixed learned weights. The next section derives its ideal Bayesian target.

The Bayesian connection

Two possible rules for the same bears.

World A favors black-and-fight and brown-and-lie-down. World B reverses that pattern. Start with equal probability on each world.

We keep the bear task and narrow the hypothesis space to two possible rules. A “match” means black-and-fight or brown-and-lie-down; this is simply the simulated rule’s label for those pairs. World A assigns survival probability p = 1/(1 + exp(−1)) to a match and 1 − p to a mismatch. World B reverses those probabilities. World A is the same data-generating rule used in the later experiment. Each world has prior probability one half. We now begin a separate, deliberately small context, adding brown-and-lie-down encounters one at a time. Features are fixed and outcomes are independent conditional on the shared world. These assumptions make every Bayesian quantity exactly computable.

p(A)=p(B)=12p(A)=p(B)=\tfrac12p(A)=p(B)=21​

In A, a matching response has survival probability p = logistic(1) ≈ 73.1%; a mismatch has 26.9%. B reverses these.

The Bayesian connection

One survival shifts the balance.

Someone lay down during a brown-bear encounter and survived. Survival was about 2.72 times as likely in A as in B, so A’s posterior weight rises to 73.1%.

For this encounter, the likelihood of survival is p under A and 1 − p under B. Their ratio is exactly exp(1). Equal prior odds therefore become posterior odds exp(1), giving posterior probability p ≈ 0.7311 for A. A new encounter with the same bear type and response survives with posterior predictive probability p·p + (1 − p)·(1 − p) ≈ 0.6068. A world’s posterior weight and an encounter’s survival probability are different quantities.

p(A∣D)=pp+(1−p)≈0.7311p(A\mid D)=\frac{p}{p+(1-p)}\approx0.7311p(A∣D)=p+(1−p)p​≈0.7311

The next brown-and-lie-down encounter has predicted survival p² + (1 − p)² ≈ 60.7%.

The Bayesian connection

More context, another update.

A second brown-and-lie-down encounter also ends in survival. The likelihood ratio compounds to about 7.39 to 1.

Conditional independence makes the likelihood a product. Two such survivors give likelihood ratio [p/(1 − p)]² = exp(2), and the same posterior odds because the prior odds are one. The posterior probability of A is logistic(2) ≈ 0.8808. The predictive survival probability is 0.880797…·p + 0.119203…·(1 − p) ≈ 0.6760. The evidence changes the mixture weights; each world’s specified rule stays fixed.

The Bayesian connection

Knowing the rule does not guarantee survival.

After four matching encounters that all end in survival, A has 98.2% of the posterior weight. The next encounter’s survival probability is still only 72.3%.

Four brown-and-lie-down survivors give posterior probability logistic(4) ≈ 0.9820 for A. The posterior predictive survival probability for the same pair is approximately 0.7227. As evidence increasingly selects A, prediction approaches p ≈ 0.7311. This is the same outcome randomness that limits prediction in the later bear experiment. Uncertainty about the world and randomness within a world are different.

The Bayesian connection

Average predictions across possible worlds.

Bayesian prediction weights each world’s prediction by how plausible that world is after seeing the table.

This is posterior predictive averaging. In our finite example, the sum runs over two worlds. In a richer model space, replace the sum with an integral. The update weights hypotheses about the data-generating process; it does not simply average the outcomes of all pretraining rows.

What pretraining buys

A foundation model practices a wider task family.

Our miniature network learned two possible bear rules. A tabular foundation model trains across many dependencies, noise patterns, sample sizes, and irrelevant features.

Our teaching model is restricted to four context rows, two binary features, and two opposed rules. It demonstrates the training objective and a learned context-dependent calculation; it does not reproduce TabPFN’s architecture, scale, or general capabilities. Expected log loss is minimized by the true conditional distribution under the pretraining task distribution. A sufficiently expressive, well-trained network can therefore approximate posterior predictive inference. This is amortization: expend computation across many tasks in advance, then reuse the trained computation for new contexts. Finite capacity, finite training, and a mismatch between the prior and the real task limit the approximation.

qθ(y∗∣x∗,D)≈p(y∗∣x∗,D)q_\theta(y_*\mid x_*,D)\approx p(y_*\mid x_*,D)qθ​(y∗​∣x∗​,D)≈p(y∗​∣x∗​,D)

θ: learned network weights. φ: a possible world. The prior lives in the task generator; θ learns how to use it.

Why the interaction matters

Two useful features. No useful first split.

Return to world A, now with many encounters and irrelevant columns. Bear type and strategy are independent coin flips: either feature alone hides the survival pattern.

We now generate data from world A of the Bayesian illustration. Both features are independent Bernoulli(0.5). The target is generated by Y = 1[−1 + 2·1(B = L) + ε > 0], with independent standard logistic noise ε. Three independent Uniform(0,1) columns contain no information about survival. The random outcome noise and the irrelevant input columns play different roles: even a predictor that knows the correct rule cannot predict every outcome.

Why the interaction matters

The combination reveals the pattern.

Survival is more likely when the response matches the bear type. The direction of the strategy effect reverses across bear types.

The four equally likely feature combinations form a noisy equality rule, or XNOR. Brown-and-lie and black-and-fight have survival probability logistic(1) ≈ 0.7311. The other two combinations have probability logistic(−1) ≈ 0.2689. Averaging either column or row gives exactly 0.5. The two predictors are jointly informative even though each is individually independent of survival.

Why the interaction matters

A small tree can express the rule.

Split on bear type, then on strategy. The second split reveals the signal, but the first split alone leaves both groups at 50%.

A depth-two tree can represent the four conditional probabilities exactly. XGBoost constructs its trees through greedy split selection, which evaluates immediate improvement rather than the benefit of a subsequent pair of splits. At a constant initial prediction, neither signal feature offers a population-level gain. This is a difficulty of discovering the interaction, not a claim that trees cannot represent interactions. Sampling variation, deeper trees, and later boosting rounds can help.

Δfirst=0,Δjoint>0\Delta_{\mathrm{first}}=0,\qquad\Delta_{\mathrm{joint}}>0Δfirst​=0,Δjoint​>0

A representable tree is not necessarily the tree found by greedy training. Sample imbalance can provide a useful first split.

Why the interaction matters

Noise offers more places to look.

A binary feature has one possible cut. A continuous distractor offers many thresholds, giving the split search more opportunities to find an accidental training improvement.

All irrelevant features have zero population predictive value, but their empirical split gains need not be zero. Maximizing over many candidate cutpoints can select a chance association. The useful binary variables have only one possible partition each. This combines with the interaction’s absent marginal signal to make continuous distractors particularly troublesome. Why the interaction matters

What might TabPFN be doing better?

Its learned inference procedure can use joint patterns in the labeled context without first making a greedy split. Pretraining on varied tasks can encourage this behavior.

The XGBoost comparisons support a diagnosis of its split-search difficulty. TabPFN offers a different way to infer a prediction rule: a pretrained network computes from the whole labeled context. Molnar’s account of synthetic task priors explains how pretraining can favor some kinds of dependencies and ways of discounting irrelevant features. Inferring the useful interaction is a plausible explanation for good performance on this task. Establishing that explanation for a particular TabPFN checkpoint requires matched experiments; attention alone would not prove it.

Why the interaction matters

Remove one more clue.

Here, both useful columns are binary and every distractor is continuous. Make the distractors binary too: does TabPFN still find the interaction?

Feature type is an additional cue in the original design. When all columns are independent balanced binary variables, being binary no longer singles out the two useful predictors. This control changes both the available split thresholds and the datatype cue, so it cannot by itself isolate a single internal mechanism. Compare the same TabPFN checkpoint and XGBoost on the same splits, with both continuous and binary distractors and several sample sizes. The current evidence establishes the XGBoost recovery; it does not establish the TabPFN result for this control.

Using one in research

The interface is familiar. The work has moved.

In the standard in-context workflow, .fit() prepares the training context; .predict() uses that context to compute predictions. The pretrained weights remain fixed.

A scikit-learn-style interface hides the change in computational workflow. Loading weights, preparing data, and building caches can occur at fit time. Prediction uses the labeled context or its cached representation. Useful defaults can reduce tuning work, but choices such as ensemble size and context selection still affect runtime and accuracy.

Using one in research

Keep the test labels outside the context.

Compare with a regularized model and boosted trees on the same held-out task. In cross-validation, each fold gets its own training context.

A pretrained predictor still needs an honest assessment on your problem. Never include validation or test outcomes in its labeled context, including through preprocessing. When selecting models or settings, keep final evaluation separate from selection. Tabular foundation models are candidates to compare, not a guarantee of better predictions or calibrated uncertainty.
