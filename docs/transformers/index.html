A row for every token

Each token position gets a row of features. The one-hot matrix selects embeddings from ; adding the positional matrix starts the residual stream.

The blue grid represents the entire matrix : one row per token and one column per feature. Our drawings use four tokens and six features; every update retains this shape.

Additive positions are our convention. Other models encode position differently.

01 / ENCODER 3 OF 8

One MLP, applied to every row

The MLP reads , after attention. It is an ordinary MLP, applied separately to each token’s feature vector with the same weights at every position.

The MLP combines features within each token row. It does not mix information between tokens.

The MLP’s output is added back to the residual stream. Biases and normalization are omitted here.

01 / ENCODER 4 OF 8

Tokens as MLP inputs

For MLP inference, each token row plays the role of one observation. Writing all rows in a matrix simply batches these separate evaluations.

Scroll to trace the rows: one row in, one row out. Each output uses only its corresponding input row, and the same weights are reused at every position.

Each input row can already contain information from other tokens, supplied by attention. The MLP does not combine rows or use a separate network per position.

01 / ENCODER 5 OF 8

Read out the sequence

The block ends with . For this encoder, mean pooling now combines its rows into one sequence representation.

A linear head maps to a scalar prediction. Pooling mixes rows as a separate readout, after the MLP.

This readout is a choice. An encoder can instead use a designated token or make predictions at individual positions.

02 / DECODER 6 OF 8

A decoder’s restricted view

Keep the block’s structure. Now each attention head may read only the receiving position itself and earlier positions.

Rows of are receivers; columns are sources. As the receiving position advances, more of its prefix becomes available. Future positions stay blocked.

We mean a decoder-only architecture. Its position-wise MLP cannot create a route to future tokens.

CONVENTIONS

One set of conventions

These choices make the diagram concrete. They are not universal model specifications.

What we chose

  • Token positions are rows; feature maps multiply on the right.
  • One block: two parallel attention heads, followed by one MLP.
  • Additive position matrix and mean pooling for the encoder’s scalar readout.
  • A separate unembedding matrix for the decoder.

What the drawing suppresses

Normalization, biases inside the block and decoder readout, dropout, and padding. Thus the equations describe a simplified block.

Standard transformer normalization acts on features within each token; adding it does not introduce token mixing. Its type and placement vary across architectures.

We show one unpadded sequence; an additional batch axis is omitted.
